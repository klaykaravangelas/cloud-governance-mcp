# Try Terraform plan analysis

Start with the checked-in samples. This walkthrough needs Python 3.14+, uv, and
the project dependencies. It needs no AWS credentials, Terraform, OPA, AI model,
or API key. The sample client sends real MCP requests directly to our local
stdio server and shuts it down when each command finishes.

## 1. Set up the checkout

Open a terminal in the repository directory, then run:

```sh
uv sync --locked --no-editable
```

uv selects Python 3.14.7 from `.python-version` and installs the locked packages
into `.venv`. If uv needs to download Python or dependencies, initial setup may
need internet access. Subsequent analysis is local. The `--no-editable` flag is
part of this project's verified workflow; see [development notes](development.md).

## 2. Discover the tool

```sh
uv run --locked --no-editable python examples/client.py --list-tools
```

Expected output:

```json
[
  "analyze_terraform_plan",
  "evaluate_terraform_policies"
]
```

[The client](../examples/client.py) starts the server using the same Python
environment, connects through the official MCP SDK, and lists its tools. It
explicitly authorizes `tests/fixtures/plans` as the server's allowed root. This
default belongs to the example client; the server itself has no default root.
Evaluation now supports one standalone RDS policy; it requires separate OPA
configuration. This analysis walkthrough still needs no OPA. Policy listing
remains planned. See [evaluation](trying-evaluation.md) when ready.

## 3. Analyze the mixed plan

```sh
uv run --locked --no-editable python examples/client.py
```

This calls `analyze_terraform_plan` with `{"plan_path": "mixed_nested.json"}`.
The client prints the full public report as formatted JSON. Compare it with the
[saved response](../examples/reports/mixed-analysis.json), generated by this same
command and checked by an automated test.

Look for these fields:

| Field | Expected value | Meaning |
| --- | --- | --- |
| `summary.total_resources` | 7 | Unique observed resources after merging both Terraform inventories. |
| `summary.changing_resources` | 4 | Managed create, update, delete and replacement entries. |
| `summary.by_mode` | `managed=6`, `data=1` | Managed infrastructure versus a data-source observation. |
| `summary.by_action` | Each of the seven buckets is 1 | Replacement counts once; reads and unreported actions have separate buckets. |
| `analysis_status` | `partial` | One inventory resource has no reported action. |
| `warnings[0].code` | `CHANGE_ACTIONS_UNREPORTED` | Its `count` is 1; the adapter does not guess that it is unchanged. |

Inspect a resource with `source: "both"`: the same address appeared in
`resource_changes` and `planned_values`, but contributes one resource to the
summary. The deleted `aws_instance.old` has `source: "resource_changes"` because
it is absent from planned inventory. The nested RDS replacement retains
`["delete", "create"]`, its module address and index `0`.

The input is [hand-authored fixture JSON](../tests/fixtures/plans/mixed_nested.json),
with fake identities. It is independent of the illustrative HCL under
`examples/terraform/analysis`; tests do not run Terraform to generate fixtures.

## 4. Try other plans

Choose another fixture with `--plan-path`:

```sh
uv run --locked --no-editable python examples/client.py --plan-path empty.json
uv run --locked --no-editable python examples/client.py --plan-path encrypted_rds.json
uv run --locked --no-editable python examples/client.py --plan-path unknown_sensitive.json
uv run --locked --no-editable python examples/client.py --plan-path partial.json
```

| Sample | What to observe |
| --- | --- |
| `empty.json` | Complete analysis, zero resources, all action buckets still present. |
| `encrypted_rds.json` | One managed create and complete analysis. No encryption/compliance decision. |
| `unencrypted_rds.json` | The same analysis as the encrypted sample: evaluating encryption is a later tool's responsibility. |
| `unknown_sensitive.json` | Two changing resources. Attribute values, secret sentinels and internal mask paths are absent from the report. An output-change warning explains partial coverage. |
| `partial.json` | One no-op resource, zero managed changes, and fixed warnings about incomplete/errored planning, deferred changes, imports, outputs and drift. |

`complete` describes coverage of this supplied plan, not whether infrastructure
is compliant or whether applying it would succeed. `partial` is a successful
analysis with coverage warnings. Resources in `no_op`, `read` or `unreported`
do not increase the managed changing count.

To exercise the SDK's legacy initialization handshake:

```sh
uv run --locked --no-editable python examples/client.py --legacy
```

It produces the same public report. The default uses SDK auto negotiation.

## 5. Check safe failures

These commands intentionally exit with status 1, print no success JSON, and put
a fixed message on stderr:

```sh
uv run --locked --no-editable python examples/client.py --plan-path malformed.json
uv run --locked --no-editable python examples/client.py --plan-path ../outside.json
uv run --locked --no-editable python examples/client.py --plan-path missing.json
```

| Input | Expected code |
| --- | --- |
| `malformed.json` | `INVALID_PLAN` — valid JSON with an invalid Terraform structure. |
| `../outside.json` | `PATH_NOT_ALLOWED` — traversal is rejected even if a file does not exist. |
| `missing.json` | `PLAN_FILE_UNAVAILABLE` — no readable regular file at that permitted path. |

At the MCP level, these are `isError=true` tool results with text and no structured
success object. The example client maps that to a nonzero exit status. Other
codes and limits are in the [specification](specifications/analyze-terraform-plan.md#error-contract-and-mcp-behavior).

## 6. Supply your own plan

Point the client at a directory you explicitly want to authorize:

```sh
uv run --locked --no-editable python examples/client.py --allowed-root /absolute/path/to/plans --plan-path plan.json
```

Use a completed, stable Terraform **plan JSON** file. A `.tf` configuration,
binary saved plan, human-readable plan output, or state JSON is not accepted.
The filename extension does not matter; content is validated. Relative plan paths
resolve against the allowed root, and symlinks beneath that root are rejected.
The example resolves an operator-supplied root to an absolute path; it passes
`plan_path` literally to the server.

For experiments inside this checkout, `local-plans/` is ignored by Git. Create
that directory yourself, put your exported JSON there, and pass
`--allowed-root "$PWD/local-plans"`. Keep the checked-in synthetic fixtures
unchanged so the automated tests and saved response remain reproducible.

If you already have a saved Terraform plan and Terraform installed, you can export
it yourself in that project's directory:

```sh
terraform show -json saved.tfplan > plan.json
```

This optional export command is for you to run, separate from this MCP server.
The server never runs Terraform or applies changes. Exported JSON may contain
sensitive values, so keep it in a directory you intend to authorize. Resource
identities appear in analysis responses; resource attribute values do not.
The accepted envelope and supported format major are documented in
[Specification 001](specifications/analyze-terraform-plan.md#accepted-plan-shape).

## 7. Connect an MCP host later

An AI host replaces our example client. It starts the same server and calls the
same tool. After setup, use these process settings in the host's configuration
format, replacing both absolute paths:

```json
{
  "command": "/absolute/path/to/cloud-governance-mcp/.venv/bin/cloud-governance-mcp",
  "args": ["--allowed-root", "/absolute/path/to/plans"]
}
```

This is the process definition, not a complete host-specific config file. Hosts
differ in where they store MCP configuration and how they wrap server entries.
Use the venv executable's absolute path so host startup does not depend on shell
activation or its working directory. No app settings are changed by this guide.

A useful first prompt is: "Use `analyze_terraform_plan` on `mixed_nested.json`.
Explain the action counts, the replacement, and why coverage is partial."
Authorize the fixture directory if using that filename.

Starting `cloud-governance-mcp --allowed-root ...` directly in a terminal leaves
it waiting for MCP messages. It has no interactive prompt or HTTP page. Use the
example client for terminal testing; it launches its own server, so a second
server terminal is unnecessary.

## Troubleshooting and verification

| Symptom | Next step |
| --- | --- |
| The server appears idle | Use `examples/client.py`, or connect an MCP host; stdio waits for protocol input. |
| `Invalid analysis configuration.` | Check that the root is an existing absolute directory and all limits are positive integers. Run the server with `--help` to inspect options. |
| `PLAN_FILE_UNAVAILABLE` | Check the filename relative to the allowed root and that it is a regular file, not a directory or special file. |
| `PATH_NOT_ALLOWED` | Use the authorized root directly; remove traversal and symlinks beneath it. |
| `PLAN_LIMIT_EXCEEDED` / `ANALYSIS_LIMIT_EXCEEDED` | Inspect the [operator limits](development.md#mcp-interface-and-stdio-a6); the server returns no truncated report. The example uses defaults. |
| Package import fails | Run `uv sync --locked --no-editable`, then use `uv run --locked --no-editable`; do not add `PYTHONPATH`. |
| Connection fails immediately | Read the fixed startup diagnostic on stderr and check the root/installation. |

For the automated checks:

```sh
uv run --locked --no-editable pytest
uv run --locked --no-editable ruff check .
uv run --locked --no-editable ruff format --check .
```

Full tests include a real local Unix-domain socket fixture. Restricted execution
environments may need host permissions for that fixture; it requires no network
service. This iteration was verified on macOS arm64. Linux execution remains
unverified here, and unsupported secure-file platforms fail startup safely.
See [acceptance evidence](analysis-acceptance.md) for checks and boundaries.

The client follows the official SDK's
[Client API](https://github.com/modelcontextprotocol/python-sdk/blob/v2.3.0/docs/client/index.md);
the optional export follows the official
[Terraform JSON format reference](https://developer.hashicorp.com/terraform/internals/json-format).
